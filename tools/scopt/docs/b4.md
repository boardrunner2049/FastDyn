## Rules (what is dead)

A store is dead iff no observer can read its bytes before they are overwritten,
on every path (`need_out ∩ bytes = ∅`). Observers per class:

| | D1 `regs[0..14]`, NZCV | D2 `neg.can_do_io` | D3 `neg.plugin_mem_value_*` |
|---|---|---|---|
| exit (S2) | every exit | direct-chain exits iff `tb_start_cb_possible` | — |
| lookup call (S3) | yes | yes (survey: every call) | — |
| flags-0 / NO_WG / plugin / noreturn call (S4) | yes | yes | yes |
| `udiv`/`sdiv` (S6) | yes | yes | yes |
| pure NO_RWG call | — | yes (survey: every call) | — |
| LDST block (S5) | yes | yes | — |
| env load of the field | yes | yes | yes |
| unclassified `rbp` access, untracked host_abs op | everything | everything | everything |

Candidates: plain `mov [rbp+d], imm/reg` writing only bytes of one deletable field
(D3's 32-bit store of an i32 access is partial and deletable), inside one guest
insn, not in an LDST block / exit stub / pool / guard stub, not in the prefix
except the `can_do_io` store there. Units with `cflags & (CF_COUNT_MASK|CF_NOIRQ|
CF_MEMI_ONLY)` are skipped (`special_cflags_unit`). D3 needs the RuntimeIdentity
fact `mem_get_value_outside_mem_cb == false` and no `plugin_mem_cbs` store in the
unit.

## Using it

```
scopt b4 census SNAPSHOT --runtime runs/wp17/admission/compute.runtime_identity.v2.json [--all-units] [--mode tcg]
scopt b4 package SNAPSHOT --store STORE --runtime RI.json [--classes D1|D2|D3] [--selftest V18.json]
scopt b4 mutants SNAPSHOT --store STORE --runtime RI.json
scopt sfb package SNAPSHOT --store STORE [--no-native]
```

`package_b4` links a `B3Plan(rewrites=…, register_slots=False)` (a **v5** file,
loader requirement `qemu-sc-v5-unmodified`), validates it with `validate_b3`
(V12 `hostsym` per rewritten unit under the strict call contract, V15, V20 with
`need_d2`/`need_d3`, V23, …) and publishes only when V12/V18 certify it.

Today's `PassManager` (B2) does not enable PURE_REWRITE: `scopt optimize` with
`pipelines/b4.toml` reports `capability_not_enabled` (fail closed). WP21 wires the
pass into the B3/B4 manager; until then use `scopt b4 package`.

## `icount-entry-sfb` is not B4

It rewrites TCG's TB entry (a baseline code-shape fix, +10.8 % measured by WP16),
breaks design invariant 3 on purpose (the entry check changes), and therefore has
its own pipeline, packager and rows. The artifact is v5; it re-imports with full
Tier-0 metadata (the B1 cross-check runs on every unit). On compute its code and
search bytes equal WP16's timed `sfb` copy (record `end_offset` differs only by the
16-byte alignment of the search table).

Things a user of the B4 path needs to know (found here):

- **RuntimeIdentity v2 per fixture config.** The fixture snapshots carry a v1
  identity; the driver extends it with `admission_facts` of the config TOML (the
  same function as `scopt admission identity`). F-B4-7 (`variable_watch` +
  preprocessing artifacts) gets `tb_start_cb_possible = true`, so its D2 deletions
  follow the conservative direct-chain rule; every other F-B4 config gets `false`.
- **Deploy with `quiet=False`.** `prepare` records the manifest with
  `log_level=20`; a deploy with `quiet=True` gives `log_level=30`, a different
  `contract_id`, and `bundle_mismatch` for the artifact and for the warm reference.
- **O2a is an icount oracle** (§9.4). In noicount the timer phase F-B4-3 has a
  host-time-dependent exception sequence: two warm runs differ as much as warm
  and B4 do. The driver gates O1/O2b (with the fixture's noicount invariants) there
  and reports O2a next to a warm-vs-warm control.
- **gdb hit counts in noicount timer phases** can livelock (every breakpoint stop
  costs host time while SysTick keeps firing): a count is used only from a gdb run
  whose QEMU exited 0, otherwise it is unknown.
- **O4 controls must sit on the observed path.** The first instance of a mutant
  shape is often in a unit that runs once and never faults. The driver also searches
  the fixture's loop unit (the label-holding unit with the largest start pc <= the
  label). `d3_before_plugin_call` cannot be detected on F-B4-7: no loaded plugin
  calls `qemu_plugin_mem_get_value` (admission fact `false`), so nothing reads
  `plugin_mem_value_*`; it stays a static-only control there.

## The B4 gate on the frozen gate binary (WP29)

Driver `tests/qemu/wp29_gate.py`, verdict `tests/qemu/verdict_wp29.py`, timing
`tests/qemu/wp29_timing.sh` + `wp29_timing_analyze.py`, report generator
`tests/qemu/wp29_report.py` → `reports/B4-gate.md`. Evidence `runs/wp29/`
(`verdict.json`). How to repeat it: `tests/qemu/README.md` (WP29) and the report's
"Reproduce" section.

Things a user of the B4 path needs to know (found by the gate run):

- **Coverage configurations get no B4 edit.** FastDyn's `coverage = true` LOG_REG
  block in front of every TB stores the PC through `index + const` (not classified by
  HostOps: `unexplained_host_store`) and spins on a full ring (a backward host branch:
  the host graph is cyclic, hostsym UNSUPPORTED). Every such unit is skipped; F-B4-10
  is vacuous. A fix belongs to HostOps/hcfg/hostsym (treat the block as one atomic
  event).
- **Re-rendering for the gate binary.** A TOML `qemu_path` wins over `--qemu`
  (FASTDYN_QEMU); the compute TOML is re-rendered with the gate path
  (`compute-base` step). Fixture TOMLs from `wp20_fixture_snapshots.py --qemu` already
  carry it.
- **Negative controls must sit where the observer runs.** The hottest unit of every
  fixture is the start-up `.bss` clear (stores of zero over zero); controls there
  are not detected. `wp29_gate.py o4-extra` orders units unique to one fixture first.
  B3 fixtures are valid detectors (F-B3-8 detects `flag_store_before_ldst`).
- **FastDyn host_abs operands exist in the fixtures.** UPDATE_MEM (F-B4-7) and LOG_REG
  (F-B4-10) stores are `movabs reg, imm64; mov [reg], …` and HostOps classifies them as
  `HOST_ABS_STORE`; V12's host_abs rule applies to them (compute has none). A real
  "host_abs pointer inside env" control (`host-abs` step) repoints F-B4-7's imm64 into
  env: V12 rejects it (`host_abs_aliases_env`), O4 detects it. The env address of a run
  can be read with a gdb diag re-run (`rbp` at a TB instruction); it moves by a few
  hundred bytes between processes with different path lengths, so target the middle of a
  guest-dead env region (`vfp.zregs` on a Cortex-M3).
- **O4 coverage of a kind:** `wp29_gate.py o4-cover` enumerates every instance of a
  kind in every gate fixture snapshot and runs each executed, untried one.
- **B4 on top of `icount-entry-sfb`:** re-import the sfb artifact as a snapshot
  (`scopt import --sc art/cache.sc --scm art/cache*.scm --manifest <base>/manifest.json
  --bundle … --runtime-identity …`) and run `package_b4` on it (`package-sfb-b4` step).
