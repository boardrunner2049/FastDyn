**Conventions.**

- Ratios are time(reference) / time(arm), so a ratio above 1 means the arm is faster.
- Log-ratios are d = log(time(reference) / time(arm)), with the same sign. They are given
  in percent (d = +1% means the arm is about 1% faster).
- Triples are always packet / uart / cli.
- `within_noise`, `above_floor` and `below_floor` are verdicts from the round-1 and
  round-2 driver. This design's own decisions use the rule in §3.7.
- "scopt O4" is this configuration. It is not FirmBOLT's `-O4` build switch, which built
  the three firmware images, and not the B3 negative-control oracle `O4`
  (`scopt/run/oracles.py`).

## 0. Summary

**The rule, in the user's words:**

> "we should have one config that include all of our good things let's call it O4.
> Do that! and O4 remains the best. Note it down as well. Whatever the best speed
> optimizations are there MUST BE included in O4~!"

On WHOPR the user added: "even without profile-guided firmlooper should help identify
hot regions."

**Three checkable properties:**

- **(I) Inclusion.** Every speed optimization that passes the add-on rule (§3.7) is in
  O4.
- **(B) Best.** In the latest campaign that times a configuration against O4, it is not
  faster than O4 on any workload, or pooled. "Faster" means a Holm-adjusted one-sided
  test at family α = 0.05 (§3.7, rule BEST).
- **(D) Decided.** Every registered pass, every firmware mode (built-in or installed), and
  every parameter of every pass O4 runs has a recorded decision with evidence. So does
  every runtime setting.

Unit tests enforce (D) and (B). The test for (B) runs against an evidence file generated
from campaign outputs pinned by sha256 (§2.9-§2.10). `docs/O4.md` records all three
properties (§2.11).

**O4 revision 1 (O4-r1) is c7b3 under a new name.**

- It runs the `sealed-pgo-7-b3` passes with the same parameters.
- The three B3 passes are switched on by the pipeline itself, through a new
  `enabled = true` entry key.
- `member_slot_skip = "on"` makes the member-skip requirement a refusal at optimize time.
- Neither change should alter `cache.sc`. Phase P1 confirms this with `cmp` (§1.7).

**Why r1 is c7b3.** c7b3 is the measured best composition: s6/c7b3 is 1.1843 / 1.1616 /
1.2415, all above_floor. Within that composition the components measure differently:

- **B3 chaining** (chain-returns and chain-static) is the gain. s6/s6b3 is 1.1782 /
  1.1850 / 1.2089 (R2), all above_floor.
- **The firmware regions** add nothing measurable on top of B3. s6b3/c7b3 is R1 1.013 /
  1.023 / 1.020 and R2 1.0167 / 0.9901 / 1.0148, all within_noise. The mean of the six
  point estimates is about +1.3%. So inside O4 the regions are measured_best as part of
  the composition, but their marginal effect is NEUTRAL. Removing them is decision X3.
- **Host-inline and the SPEC bundle** (specialize-returns, constant-propagation,
  branch-folding, dead-host-ops) were included as a bundle and never isolated.
  constant-propagation is the one item labelled HARMFUL (0.943× on the fixture).
  Ablations X1, X2 and X4 are mandatory.

**Deciding is tuned to the measured noise (§3.3-§3.7).** The block log-ratio SD of
byte-identical fast-tier pairs is 3.7% / 7.0% / 3.1%. At round 2's 20 / 10 / 10 blocks
that cannot resolve add-ons of 2% or less. The plan therefore runs in stages:

1. **Screen (campaign A):** one campaign with every light arm, an o4-aa copy of o4 and the
   anchors. It drops arms whose bytes equal o4's and arms that are clearly slower.
2. **Head-to-heads (campaign A2):** each surviving candidate runs three arms, [o4, o4-aa,
   X], with 40 / 80 / 40 blocks. It runs only on the workloads where X's bytes differ.
3. **Heavy arms (campaign H):** A5, A6 and w7bd_b3 run in a separate campaign, so their
   carry-over does not inflate anyone else's variance.
4. **Decision:** the Hodges-Lehmann estimate of the block log-ratios against the pooled
   reference sqrt(o4·o4-aa), pooled across workloads by inverse variance. An add-on is
   accepted on a one-sided 95% lower bound above 0, Holm-adjusted across candidates, with
   non-inferiority of −2% on every workload. Removals and the fidelity item need
   non-inferiority and no detectable loss.
5. **Confirmation (campaign B):** O4-r2 is re-timed with a fresh seed, and a best-check
   is run against every other arm.

**The main mechanistic risk is still bypass.** B3's chain slots jump past the lookup
through which regions are entered. c7b3's regions are entered about 53 times per packet
run, against 41,700 for p7. Any candidate that adds regions (A1, A7, A8, I1, C1, C1p, A5)
is checked with a regions replay before timing (§3.2). Making B3 slots enter regions
(U7) is the structural fix, and it is out of scope here.

**FirmLooper and WHOPR in O4.**

- **WHOPR planner.** O4 keeps it. It never removes a candidate, but its partition order
  is the order in which regions are priced. Through the stable "covered" sort and the
  `captured` flow, that order changes which roots are admitted: the legacy planner admits
  2 more roots on packet and swaps one on cli. A8 decides the planner.
- **WHOPR configuration (exhaustive selection).** Unpriced, it is measured slower
  (w7bd_b3). Priced, as A5, it is a challenger in campaign H.
- **FirmLooper.** It finds task loops without a profile. O4 needs the profile anyway,
  for B3. The user's idea, "FirmLooper finds, PGO prices", is C1p, which needs no code.
  Under pricing, every FirmLooper-only root the probes saw is refused unless the profile
  saw it called. The one admitted root, the 14-call memset, is also admitted by A7. So
  the union mode A2a lands only if A7 or C1p shows a signal.
- A profile-free O4 is not possible: B3, which carries the gain, needs the profile.

## 1. O4 definition

### 1.1 Scope

**What O4 is.** O4 is one scopt pipeline plus the inputs and runtime contract it needs.
It targets trusted sealed captures: the whole firmware is pre-translated, the run is
icount-off, and the output is a composed canonical v7 artifact (sc6 extension at 0x100,
trusted firmware directory at 0xFF00).

**What O4 is not.**

- It does not cover the ordinary (non-sealed) tier, where SFB+B3 (c5) is the measured
  configuration.
- It does not cover runs without a profile.

`-O4` refuses both cases (§2.7), and `docs/O4.md` names them as out of scope.

The file is unchanged since the first version of this design. It is
`/data/scfix-o4/design/pipelines/O4-r1.toml` and becomes
`tools/scopt/pipelines/O4-r1.toml`.


**Differences from `sealed-pgo-7-b3.toml`:**

- the name, description and header comment;
- `enabled = true` on the three B3 passes;
- `member_slot_skip = "on"`.

**`O4.toml`** has the same passes, with name `"O4"`. A test asserts that it equals the
newest `O4-rN.toml`. `pipeline_id` hashes the passes, so archived artifacts stay
reproducible, and every frozen revision stays loadable by name.

**Compatibility of the `enabled` key.** Older scopt builds reject the key
(`_strict_keys` on pass entries). That includes the editable install in
`/data/trebuchet-clean/FastDyn/scopt-env`, whose `_ENTRY_KEYS` is
`{"name", "version", "params"}`. So the O4 TOMLs, the arm TOMLs and any sidecar that
records them can be read only by scopt at or after the O4 commit.

- This is deliberate. An older tool fails loudly instead of running O4 without B3.
- The alternative, an `x_enabled` key, is rejected: `_strict_keys` lets `x_*` keys
  through, so older tools would silently drop B3.
- `enabled` stays out of every existing pipeline, because older tools replay those.
  `sealed-pgo-7-b3.toml` gets a comment only.

### 1.5 Prerequisites and runtime contract

**Prerequisites.** They are c7b3's; inventory §2 has the exact commands.

1. A trusted sealed capture: `prepare_sealed_firmware.py … --trust-user-no-recovery`,
   then `scopt bundle identity`, `fastdyn compile-launch`, the runtime identity and
   `scopt import`.
2. A sealed steady profile:
   `scopt profile run -c <sealed config> --snapshot S --qemu <capable qemu> --sealed --trusted --phase steady@<marker> --inputs <train input> --out <dir>`.
   The markers are packet 0x833e8, uart 0x822fc and cli 0x82fc4.

**Runtime contract**, for every O4 launch:

- QEMU has counters revision 4 and member skip, as recorded in
  `scopt/data/qemu_capabilities.json` (§2.8).
  - aacca05, sha256 `951775b0…eebc60`, is capable.
  - a1bdec6, `026f8e8b…630295`, is not: its loader exits on the first member flag
    (`sc7_die` → `exit(EXIT_FAILURE)`). So does the a79d340 source in
    `/data/trebuchet-clean` (`supercache.c:1151-1152`).
- The QEMU that runs must be the one the artifact targets. FastDyn's supercache setup
  checks that sha256(qemu executable) equals the artifact's `qemu_sha256` for composed
  v7 artifacts (§2.8).
- `-accel tcg,supercache=<artifact>/cache.sc`, with no `-icount`.
- The environment sets `QEMU_SC_SEALED=1` and `QEMU_SC_TRUSTED=1` and nothing else of
  that family: no `QEMU_SC_V7_EXPERIMENT`, no `QEMU_SC_SEALED_SKIP_IRQ`, no
  `QEMU_SC_*_STATS`, no `QEMU_SC_PROFILE`.
- The plugin `libfastdyn.so` with `coverage=0`, and `FASTDYN_TIMING=1`.

If X3 is accepted (regions removed), O4 needs only an sc6-capable QEMU, and the
member-skip clause disappears.

### 2.4 `hot-loop-tasks`, the union only (A2a; deferred)

Land this only if A7 is accepted, or if C1p's pooled estimate against o4 is positive.
On these images A7 already contains its one addition. The policy:

```python
def _hot_loop_tasks(inputs):
    """Hot-loop roots, unchanged, plus FirmLooper v3 task-loop roots the profile did not
    nominate.  Discovery stays hot-loop's (firmware-calls); v3 loops only nominate roots.
    Hot and 'both' roots expand exactly as hot-loop; v3 boundaries (with its ISB rule)
    apply only to static-only roots, which are priced after every hot root."""
    if inputs.profit is None:
        raise PolicyError("hot-loop-tasks needs the firmware cost model")
    if inputs.params.get("nested", "profit") != "profit":
        raise PolicyError("hot-loop-tasks prices nested calls (nested must be 'profit')")
    hot = _hot_loop(inputs)
    loops = _v3_loops(inputs)
    static = _firmlooper_v3(replace(inputs, task_loops=loops))
    hot_set, static_set = frozenset(hot.roots), frozenset(static.roots)
    static_only = tuple(c for c in static.roots if c not in hot_set)
    late = frozenset(static_only)
    roots = tuple(hot.roots) + static_only
    refusals = {c: hot.refusals.get(c) or static.refusals.get(c)
                for c in (hot.refusals.keys() | static.refusals.keys()) - frozenset(roots)}
    evidence = {c: {**static.site_evidence.get(c, {}), **hot.site_evidence.get(c, {}),
                    "o4_evidence": [n for n, hit in (("profile_hot_loop", c in hot_set),
                                                     ("static_task_loop", c in static_set)) if hit]}
                for c in hot.site_evidence.keys() | static.site_evidence.keys() | frozenset(roots)}
    by_site = {(c.source_uid, c.insn_vaddr): c.callsite_id for c in inputs.calls}
    inner = hot.expansion
    def expansion(site, context):
        root = context[0] if context else by_site.get((site.source_uid, site.source_pc))
        if root in late:
            action = static.expansion(site, context)
            if residual_reason(action):
                return action
        return inner(site, context)
    expansion.report = inner.report            # keeps nested_decisions in the receipt
    return PolicySelection(roots, refusals, evidence,
                           {"task_loops": loops.report(), "hot_loop": dict(hot.evidence),
                            "union": {"hot": len(hot_set), "static": len(static_set),
                                      "static_only": len(static_only),
                                      "both": len(hot_set & static_set)}},
                           expansion=expansion, expand_nested=True, price_after=late)

# _BUILTINS: no discover_loops, so WHOPR uses the firmware-whopr analysis as hot-loop does.
"hot-loop-tasks": FirmwarePolicy(_hot_loop_tasks, expand_nested=False, requires_edges=True,
                                 cost_model_default=True),
```

**Supporting changes:**

- `PolicySelection` gains `price_after: frozenset[str] = frozenset()`.
- `firmware_inline.py` sorts the priced work by `(callsite_id in price_after, covered)`.
  `covered` for a root outside `price_after` counts only plans outside `price_after`.
- Roots outside `price_after` are priced with
  `trusted_entries = {callers of planned roots outside price_after}`. Roots in
  `price_after` see every caller.
- So hot roots are planned, ordered and priced exactly as under hot-loop. A
  static-only root admitted later is entered through a trusted entry that the hot regions
  were not charged for. That is at most one dispatch per such exit, and it is on the
  favourable side for the hot roots.

**Why discovery stays hot-loop's.** v3 discovery adds 26 / 25 / 12 calls. Every one of
them has 0 profiled calls or a RTOS-boundary refusal, so pricing would refuse each
anyway. Using v3 discovery would also change `NestedProfitExpansion`'s call table and
the WHOPR summary. Those are two of the drift sources the review found.

### 2.7 `scopt optimize -O4`: preflight and post-run stage gate (`scopt/commands/optimize.py`, `scopt/manager_b3.py`)

**Selecting O4.** `-O 4` is mutually exclusive with `--pipeline` and resolves to
`PIPELINES_DIR / "O4.toml"`, never `$SCOPT_PIPELINES_DIR`.

**When the preflight runs.** It runs whenever the loaded pipeline's name matches
`^O4(-r\d+)?$`, so `--pipeline O4` or `--pipeline O4-r1` cannot bypass it. Arm files are
named `o4-…` in lowercase and are not affected.

**What the preflight checks.** It fails fast with one `click.UsageError` that names every
problem and points to `docs/O4.md` "Using O4". It requires:

1. **No customization.** `--disable`, `--only`, `--params`, `--enable` and a non-`auto`
   `--pgo-phase` are rejected: "O4 is fixed; copy O4-rN.toml under another name to
   experiment".
2. **Inputs.** `--runtime-identity`, `--prep`, `--elf` and at least one `--profile`.
3. **Profile.**
   - `exact_loop_profile(view, snap.snapshot_id, "steady")` is true. That means an exact
     source, `complete`, method `exact_dispatch_unchained_v1`, no overflow, chain
     disabled, and the steady phase reached.
   - `profile_phase_info(prof, "steady", snap units)` gives a match of at least
     `DEFAULT_MIN_PROFILE_MATCH` (0.95).
4. **Snapshot.**
   - icount off: `run_info.flags & RunInfoFlag.ICOUNT_ENABLED == 0`.
   - Sealed: no unit key has `CF_PCREL`, the test `resolve_entry_chain` uses. If the
     import records an explicit sealed marker, use that instead.
   - Otherwise: "O4 targets sealed icount-off captures; for ordinary captures use the
     SFB+B3 recipe (docs/b3-passes.md, configuration c5)".
5. **Runtime.** The `--runtime-identity` exe digest is looked up in the capability table
   (§2.8).
   - Known incapable: refuse, even if a flag or environment variable lists the digest.
   - Known capable: implicitly allowlisted for v6, trusted v7 and member skip.
   - Unknown: the digest must be in all three of `v6_capable_exes`,
     `trusted_v7_capable_exes` and `member_skip_capable_exes`, and the message names the
     missing flag and its environment variable.
6. **PGO launch.** Needed only when the loaded O4 has a `hot_loop_only` host-inline. It
   can come from `--pgo-launch`, `<prep>/launch.json`, or `<prep>/run.toml` with
   `fastdyn` on PATH, mirroring `_automatic_loop_pgo`.

**Post-run stage gate, before publishing.** `optimize` passes
`required_stages = {every O4 pass}` to `optimize_b3`. Next to the existing FAILED check
(`manager_b3.py:999`), each required pass is classified with
`run/pass_policy.stage_status`.

- **Accepted:** `edited` and `no_change`. In addition, firmware-inline
  `SKIPPED_UNKNOWN` with reason `no_profitable_call`, `no_eligible_call` or
  `no_firmware_call` counts as no_change: a firmware with nothing worth a region.
- **Anything else rejects** with reason `o4_stage_degraded`, naming the pass, its status
  and its reason, and exits 2 with nothing published. The cases include:
  - `missing_profile` and `profile_phase_not_reached` (`manager.py:943-949`);
  - `profile_incompatible`;
  - `hot_loop_exact_profile_required` and `cost_model_exact_profile_required`;
  - `guest_image_missing`;
  - `incomplete_lookup_profile`;
  - `policy_disabled`.
- The JSON result carries `effective_configuration()`.
- Checked against round 2: every c7b3 receipt classifies as edited or no_change.

**Tests** (CliRunner and unit):

- `-O4` together with `--pipeline` is a usage error.
- `--pipeline O4` runs the preflight.
- `-O4` with `--params` or `--disable` is a usage error.
- An inexact or unreached profile is refused.
- An icount-on snapshot fixture is refused.
- a1bdec6's digest is refused even with `--v7-member-skip-exe` set to it.
- An unknown digest without flags is refused.
- The prep fallback satisfies the launch requirement.
- A fixture where chain-static returns `incomplete_lookup_profile` exits 2 with nothing
  published.

### 2.10 Evidence generator (`tools/scopt/scripts/o4_evidence.py`)

**Input.** For each campaign directory:

- the driver's `summary.json`;
- the pre-registered `decide.json` from `decide.py` (§3.7);
- `plan.json`, which gives the same-bytes list.

**Output.** `docs/o4-evidence.json`, schema `scopt.o4-evidence/2`.

- `sources`: one entry per file, with path, sha256, campaign and TIMING.md section.
- `rows`, each with:
  - `revision`, `campaign`, `workload` (or `pooled`), `reference`, `arm`;
  - `d`, `se`, `lb95`, `ub95`;
  - `holm_family` and `holm_rank`;
  - `verdict`, one of `faster_than_o4`, `slower_than_o4`, `not_shown` and
    `same_bytes`;
  - `summary_sha256` and `decide_sha256`;
  - the driver's median ratio and CI, for continuity.
- Arms are named as in the campaign; O4 is `"O4"`.

The generator is the only writer. Re-running it on the pinned sources must reproduce
the file byte for byte, and a CI check does that whenever the sources are present.

**Seeding r1.** Round 2 has no `decide.json`, so the round-2 and bounded-round
`summary.json` files are pinned and their c7b3 rows are converted with `decide.py` run
on their `observations.jsonl`. They become rows for `"O4"`, with
`via: "c7b3, same cache.sc bytes (sha256 …)"`. This happens only after §1.7 shows equal
bytes. Every earlier-revision row is kept when r2 lands.

- B: about 50 minutes.

### 3.2 Build gates (per arm and workload)

**Correctness (G0).** Failing any of these makes the arm unsafe.

- Optimize rc 0 and the artifact published.
- The round-2 functional check passes:
  - 16 words and 1 BENCH line on every case;
  - `counters_revision == 4` and `counter_problems == []`;
  - every poll entry verified;
  - `chain_skipped_trusted_poll_unverified == 0`;
  - for sc6: `invariant_violations == 0` and `flush_resets == 0`.
- The loader requirement is `…+sc6+member-skip`, or sc6-only for `o4_noregions` and
  `b3l`.
- `x_b3.firmware_region_links` refusals are 0.
- The launched QEMU's sha256 equals the artifact's `qemu_sha256`.

**Regions replay**, for every arm with regions, recorded before timing: activated
regions, entries through lookup, residual exits and slots skipped, per case.

- **A1 gate.** Compare `o4_chained` with `o4`.
  - If the added regions show no activations and no change in entries beyond the
    run-to-run variation, record A1 as "inert". The expected effect is then 0.
  - If they are entered, A1 is "entered, possibly slower" (§1.8).
  - In both cases A1 still goes to the screen; the gate sets the prediction.
- The same replay is recorded for A7, A8, I1, C1, C1p and A5.

**Validity.** Failing any of these means the arm does not test what it claims.

- **`o4`:**
  - receipts as c7b3's: host-inline 1 / 0 / 0; regions 48 / 19 / 7; chain-returns
    47 / 43 / 28; chain-static 256 / 50 / 43;
  - `cache.sc` equal to c7b3's.
- **`o4_chained`:** regions about 56 / 23 / 7; cli the same bytes as `o4`.
- **`o4_isb`:**
  - `policy.isb_boundary` is true;
  - at least 33 `isb_boundary` exits on packet, 2 on uart;
  - cli the same bytes as `o4`;
  - `nested_decisions` count equal to `o4`'s;
  - every member difference from `o4` is a successor of an ISB-ending member.
- **`o4_rank`:** chain-static applied, not `incomplete_lookup_profile`;
  `c_target_check = 0.0` in its receipt; slots and refusals by reason.
- **`o4_hotgraph`:** about 13 / 20 / 2 sites; `helper_lookup_tb_ptr` gets 0
  (`helper_graph_size_policy`); SPEC variants recorded against 0 / 9 / 1.
- **`o4_min2`:** regions about 52 / 26 / 13, and every added root priced.
- **`o4_legacy`:** regions about 50 / 19 / 7; uart the same bytes as `o4`.
- **`o4_nohi`:** no host-inline receipt.
- **`o4_nocp`:** constant-propagation absent.
- **`o4_nospec`:** the four SPEC passes absent.
- **`o4_noregions`:** no firmware directory.
- **`fl3b3`, `fl3b3p`:** 15 / 7 / 5 and 3 / 3 / 2 regions, with member descriptors.
- **`b3l`:** the layout passes ran; record whether the bridge or Pettis-Hansen was
  used. If they refuse on sealed snapshots, C2 is dropped and the reason recorded.
- **`o4_pwhopr`:** admitted and refused roots, members, growth, build time and memory.
  Abort above 8 GB RSS or 60 minutes.
- **`o4_hostall`:** about 1,005 / 1,455 / 1,472 sites.
- **`o4_tasks`** (if built):
  - the `union` counts present;
  - every hot root embedded by `o4` is embedded with the same members and `source_uids`,
    and `profit.net_ns` within max(1 ns, 1e-6 relative);
  - `nested_decisions` equal to `o4`'s.
- **Same bytes.** `cmp` every arm's `cache.sc` against `o4`'s. An equal pair is recorded
  as `same_bytes` and that arm is not timed on that workload. The expected same-bytes
  pairs are:

### 3.3 Noise, estimator and power

**Measured noise.** The table below uses round 2's `observations.jsonl`, with block sums
over cases. The pair c7b3_not2t / c7b3 has byte-identical caches on all three workloads.

| | packet | uart | cli |
|---|---:|---:|---:|
| SD of block log-ratios, c7b3_not2t / c7b3 | 3.66% | 7.00% | 3.12% |
| Blocks in round 2 | 20 | 10 | 10 |
| SE of the median, 1.25σ/√n | 1.02% | 2.77% | 1.23% |
| Bootstrap SE: median / Hodges-Lehmann | 0.94% / 0.86% | 3.47% / 2.50% | 1.32% / 1.06% |
| Minimum detectable effect, median, 80% power, two-sided 5% | 2.9% | 7.8% | 3.5% |

**Consequences for the version-1 rule, all now replaced:**

- Under the null, G2b's k ≥ 0.7n holds with p = 0.172 at n = 10 and 0.058 at n = 20.
- G1's r ≥ 0.98 rejects a truly neutral item on uart about 23% of the time.
- G3's r ≥ 1.00 is a coin flip for a null item.
- Every add-on predicted at 2% or less could pass only by luck.

**Estimator (pre-registered).** For candidate X on workload w, take each block b except
the burn-in block 0:

    l_b = log( sqrt(T_b(o4) · T_b(o4-aa)) / T_b(X) )

where T_b is the block sum over cases.

- d_w is the Hodges-Lehmann estimate of the l_b, the median of the Walsh averages.
- SE_w is the SD of 20,000 block-bootstrap resamples of d_w, seeded with
  `f"{seed}:{w}:{X}"`.
- Pooled over the workloads where X's bytes differ:
  d = Σ(d_w / SE_w²) / Σ(1 / SE_w²), and SE = (Σ 1 / SE_w²)^−½.
- One-sided 95% bounds: LB = d − 1.645·SE and UB = d + 1.645·SE, and likewise LB_w and
  UB_w.

**Why these choices:**

- HL beats the median on these data (0.86 against 0.94%, 2.50 against 3.47%).
- A pooled reference stops a slow or fast o4 from moving every comparison together, as
  the packet bias did in round 2 and in the bounded round. If per-run noise is
  independent, it also cuts the SD by about √(3/4).

**Projected power of a head-to-head** (40 / 80 / 40 blocks, HL, pooled reference):

- SE_w is about 0.53% / 0.77% / 0.46%.
- The single-workload minimum detectable effect (one-sided 5%, 80% power) is about
  1.3% / 1.9% / 1.1%.
- Pooled over three workloads, SE is about 0.32%. The minimum detectable effect is about
  0.8%, or about 1.1% at Holm's first step with about 10 candidates.

### 3.7 Decision rule (written before the data)

**Pre-registration.**

- `decide.py` is `/data/scfix-o4/driver/decide.py`. Its sha256 is written into every
  plan as `x_decide_sha256` before the run.
- It reads `observations.jsonl` and `plan.json` (which carries the same-bytes list),
  computes §3.3, and writes `decide.json`.
- The driver's median statistics are still reported, but they decide nothing.

**VALID.** For each workload, compute the o4 / o4-aa HL estimate a_w with a two-sided
99% bootstrap interval.

- If that interval excludes 0, the workload is biased. Rerun that workload's campaign
  once with the seed + 100.
- If it is still biased, decide with a `reference_bias` flag recorded on every row.

**G0 (correctness).** All §3.2 correctness gates pass on all three workloads.
Otherwise X is excluded as `unsafe`, whatever its speed.

**ADD**, for add-ons A1, A3, A4, A6, A7 and A8, plus A2a if built. Accept X iff all of
these hold:

1. G0.
2. Holm across the family F of add-ons decided in A2 and H: sort the one-sided pooled
   p-values p = 1 − Φ(d / SE) in ascending order; X is accepted when every p up to and
   including X's satisfies p_(j) ≤ 0.05 / (|F| − j + 1).
3. Non-inferiority on every differing workload: LB_w > log(0.98).

**REMOVE**, for removals X1-X4, and **FIDELITY**, for I1. Accept (remove the component,
or include the rule) iff all of these hold:

1. G0.
2. UB ≥ 0: a loss is not shown.
3. LB > log(0.99): the pooled loss is under 1% at 95%.
4. LB_w > log(0.98) on every differing workload.

An item whose bytes equal o4's everywhere is removed (removals) or included (I1) for
free. A removal that also passes ADD is a speed gain in its own right.

**BEST (the B property).** In every campaign, every arm A other than o4 and o4-aa gets
pooled and per-workload one-sided p-values for "A faster than O4". A Holm family per
campaign covers all of them.

- Any rejection at 0.05 means a configuration is faster than O4. If it is a candidate,
  ADD normally accepts it already.
- Otherwise (a challenger or an anchor), it becomes the base candidate for O4-r2: O4
  must absorb whatever makes it faster, or document why it cannot be composed.
- `test_no_recorded_arm_beats_o4` fails in the meantime.

**Groups and conflicts.**

- **Host-inline (A4, A6, X1).** If several are accepted, take the highest pooled d.
  Within 0.3%, prefer X1, then A4, then A6.
- **X3 against the firmware items.** X3 applies only if no firmware add-on (A1, A7, A8,
  A5) is accepted. Otherwise the regions stay, and X3 is recorded as "removable,
  superseded by an accepted firmware add-on". I1 is moot under X3.
- **X2 and X4.** If X4 is accepted, X2 is moot.
- **A1, A7, A8 and I1** compose.

**Exclusions are recorded with their numbers.** Each gets d, SE, LB and UB, pooled and
per workload, with its Holm rank. They go into `scopt/o4.py`, `docs/o4-evidence.json`
and `docs/O4.md`. There are no silent drops.

## 4. Risks, and what makes an add-on unsafe

**Correctness comes first.** An add-on is unsafe, and excluded whatever its speed, if it:

- fails G0;
- needs a runtime token, environment variable or QEMU outside the contract;
- relaxes `trust`, `interrupts` or `icount`;
- needs `QEMU_SC_SEALED_SKIP_IRQ` or `no-sealed-sc6`;
- leaves a poll entry unverified;
- writes guest executable pages;
- makes the loader fall back silently;
- leaves a required pass degraded. `-O4` now refuses that (§2.7).

**Specific risks:**

1. **Wrong QEMU.**
   - A pre-counters-revision-4 loader exits on a member flag.
   - Mitigations:
     - the capability table, which overrides flags for known-incapable digests;
     - the `-O4` preflight;
     - FastDyn's launch-time digest check;
     - the driver check.
   - The remaining gap: an unknown digest passed by hand. The docs say to confirm counters
     revision 4 first.
2. **A degraded artifact published under the name O4.** Closed by the preflight's
   profile, snapshot and runtime checks and by the post-run stage gate.
3. **Chained pricing (A1).**
   - It double counts the lookup credit B3 already collects, up to about 6 ns per
     guarded lookup. It also prices residual exits as chained on pre-B3 member copies.
   - An entered A1 region can be slower than the B3 public code it replaces.
   - The regions replay sets the prediction, and the head-to-head decides.
4. **Deferred yields (I1).**
   - Without I1, a PendSV that cloned kernel code requests just before an ISB is taken at
     the region exit. The trusted contract allows that, and every functional check passed.
   - For a task that has just blocked itself, the deferral lasts until the region exits.
     On other firmware a long callee region could delay the switch noticeably.
   - I1 is decided on fidelity grounds, provided it costs no measurable speed. If it
     does, `docs/O4.md` names the deferral sites.
5. **Regions bypassed by B3** (A1, A7, A8, I1, C1, C1p, A5). As in version 1; U7 is the
   fix.
6. **Pricing order.** The WHOPR partition order changes admission (A8). Any future
   change to partitioning can change O4's bytes. §1.7 step 1 catches that for existing
   pipelines.
7. **Full-graph host-inline (A4, A6).** As in version 1: BASEPRI and hflags updates in
   translated code, the 32768 cap, SPEC loss on spliced units, and the replay retry.
8. **Priced exhaustive (A5).** Deep recursive regions; the sc6 arrays must end before
   0xFF00; build limits in §3.2.
9. **Union selection (A2a).** Only if built. The superset is exact by construction and
   by test 5. Do not join receipts across arms by callsite id: ids hash `source_hash`.
10. **`enabled` key.** Older scopt cannot read O4 pipelines or their sidecars (§1.4).
11. **Measurement.**
    - The noise is 3.7 / 7.0 / 3.1% per block, and uart is bimodal for w7-class arms.
    - The packet reference bias appeared in both directions.
    - cli's block 0 was disturbed twice.
    - The mitigations: the pooled reference, the HL estimator, the burn-in block and
      settle time, the heavy arms isolated, Holm against the winner's curse, and B1's
      fresh seed.
12. **Generalization.** The evidence comes from three FirmBOLT `-O4` images with one
    training input each, and the profit constants were never swept. A new workload class
    needs its own campaign before O4 is claimed best on it.
13. **Provenance and concurrency.** Frozen revisions are never edited. Nothing lands
    before the `treb-wip` push, and the commits stay separate.

  on cli and leaves uart unchanged. The planner is therefore a decided knob (A8).
- **(b) Member skip.** `member_slot_skip` is NEUTRAL (enabling) in §1.2.
- **(c) A1 counts.** They are measured alone in probe2: 56 / 23 / 7. The value
  extrapolated from the combined probe was 56, which matched.
- **(d) `enabled` key.** Older scopt builds, including `/data/trebuchet-clean`'s
  scopt-env, cannot read O4 pipelines or their sidecars. This is documented (§1.4), and
  `enabled` stays out of existing pipelines. `x_enabled` is rejected because older tools
  would silently run without B3.

**Other changes in this revision:**

- `o4_all` is dropped: a composition is built from accepted items and confirmed by B1.
- `s6-aa` is dropped: the band is o4 / o4-aa.
