# B5 campaign: definition, prep, freeze, check, plan, run, diag, report (WP30)

Design: `docs/design/B3-B4-design.md` §10 (arms §10.1, metrics §10.2, model §10.3) and §11
("B3 performance", B4 item 5). Plan: `docs/design/IMPLEMENTATION-PLAN-B3B4.md` `## WP30`.
Priorities: the maintainer's evaluation report `WP16-probe.md` (not in the repository) (R11 decision). Report: the maintainer's evaluation report `B5-plan.md` (not in the repository).

WP30 **defines** the campaign; it times nothing. `prep`, `freeze`, `check` and `plan` are
untimed. `run` is the only timing command; it belongs to the B5 execution stage.

| piece | file |
|---|---|
| definition (hand-written: arms, recipes, sets, rules, priorities) | `campaigns/b5-freertos.def.toml` |
| frozen campaign (generated by `freeze`, never edited) | `campaigns/b5-freertos.toml` |
| driver: prep / freeze / check / plan / run / diag / report | `tests/qemu/b5_campaign.py` |
| B5 report section (`scopt report --b5-campaign`) | `scopt/report/b5.py` |
| unit tests | `tests/unit/test_wp30_b5.py` |

## Arms

All arms run on the frozen gate binary `qint-v6-gate-1` and deploy against the
gate-binary compute base of WP28 (WP29's base has the same snapshot id, TOML and cache
bytes; `prep` checks it).

| arm | category | obtained by |
|---|---|---|
| `nocache`, `empty` | baseline | derived by `scopt run` |
| `warm` | reference | the base snapshot |
| `identity` (v5), `identity-v6` (empty ext table) | control | built: `optimize --pipeline identity`; `package_b3(B3Plan(force_v6=True))` |
| `layout` | b2 | built: `optimize --pipeline b2-layout` with the base's train profile |
| `b3-chain`, `b3-static`, `b3-spec`, `b3` (all six B3 passes) | b3 | reused: WP28's published compute artifacts |
| `b4` | b4 | reused: WP29 |
| `sfb` | **baseline_tcg_fix** | reused: WP29. Never counted as caching, B3 or B4 |
| `sfb-b4` | b4 (parent `sfb`) | reused: WP29 |
| `layout-no-{cluster-hot,order-cold}` | ablation of `layout` | built |
| `b3-no-<pass>` for the six B3 passes | ablation of `b3` | built: `optimize --pipeline b3 --b3 --disable <pass>` |
| `b4-D1`, `b4-D2`, `b4-D3` | per-class ablation of `b4` | reused: WP29 |
| `semantic`, `combined`, `semantic-no-<pass>` | **skipped_unsupported** | `capability_not_enabled` (below) |

`semantic` (B3 + B4 in one artifact) needs a packager that certifies B4 deletions inside
the B3 manager: `optimize_b3` builds hostsym inputs with `build_contract` and no
`need_d2`/`need_d3`, while B4 deletions are certified only by `package_b4`
(`StrictCallContract`, V15 deletable class). `combined` additionally needs B2 layout
together with B3 edits, which `optimize_b3` refuses (WP21 note 15). The substitutes
`b3` (the B3 part) and `b4` are timed instead, and the ablations are taken on top of
them. The report lists every unsupported arm as a `skipped_unsupported` row in every
split.

Excluded (rows, not timed): `layout-no-hotcold-partition` (degenerate), WP16's experimental
copies (`cmov` crosses a guest-insn boundary; `gce`/`d1`/... never published), blinky (no
gate-binary base), and any arm whose `cache.sc` equals an earlier arm's (duplicate).

## Sets

| set | split | arms | reps × inputs |
|---|---|---|---|
| `compute-train-calib` | train | warm, b3-chain, b3-static, b3-spec, b3, b4, sfb | 30 × 3 |
| `compute-heldout-core` | heldout | 13 core arms | 30 × 3 |
| `compute-heldout-ablation` | heldout | warm + parents + 11 ablations | 30 × 3 |
| `compute-final-core` | final | 13 core arms | 30 × 3 |
| `compute-final-ablation` | final | warm + parents + 11 ablations | 30 × 3 |

Each set is one `scopt run` campaign: interleaved and paired (per rep the inputs are
shuffled, per (rep, input) the arms, `random.Random(seed)`), distinct seeds 3001-3005.
The train set only re-derives the per-lookup and per-store savings on the gate binary
(the WP16 constants are qint's, D-EV-2); it never gives a headline number. The final split
runs last, after `check` passes again.

## Commands

```
B=tests/qemu/b5_campaign.py; PY=python
$PY $B prep   --out $FASTDYN_ROOT/runs/b5/prep                      # untimed
$PY $B freeze --prep $FASTDYN_ROOT/runs/b5/prep/prep_summary.json \
              --out campaigns/b5-freertos.toml                                   # then commit it
$PY $B check  --campaign campaigns/b5-freertos.toml --expect-sha256 <hex>       # freeze checker
$PY $B plan   --campaign campaigns/b5-freertos.toml --expect-sha256 <hex> \
              --out $FASTDYN_ROOT/runs/b5/plan                      # dry run, no QEMU
# --- B5 execution stage only (timing) ---
$PY $B run    --campaign campaigns/b5-freertos.toml --expect-sha256 <hex> \
              --out-root $FASTDYN_ROOT/runs/b5/timing --cpus 8-11
$PY $B diag   --campaign campaigns/b5-freertos.toml --expect-sha256 <hex> \
              --out-root $FASTDYN_ROOT/runs/b5/timing                # untimed
$PY $B report --campaign campaigns/b5-freertos.toml --out-root $FASTDYN_ROOT/runs/b5/timing
```

* `freeze` refuses when prep did not pass, when a timing campaign on a final input exists
  on the gate binary, or when the scopt package, `pipelines/`, the definition or the driver
  have uncommitted changes. It records the held-out and train timing campaigns that already
  ran on the gate binary (WP28/WP29 reported rows) in `freeze`.
* `check` recomputes: the campaign file sha256 and that it is committed; the scopt tree,
  pipelines tree, driver, helper and definition blobs at HEAD; the gate tag commit; the gate
  exe sha256 (file and the maintainer's evaluation data (not in the repository)); plugin; firmware sha256/size/mtime;
  base TOML; snapshot `cache.sc` (sparse) and `snapshot.json`; training profile file and
  id, and that its inputs are train only; RuntimeIdentity; calibration; per arm the
  `cache.sc`, `MANIFEST.sha256`, artifact id and directory name, no negative-control tag;
  per set the input manifest and files, reps >= 30, warm present, every ablation's
  parent present; distinct seeds.
* `run` re-executes itself under `flock $FASTDYN_ROOT/runs/.timing.lock`, pins `scopt run` with
  `taskset` to at most 4 CPUs, samples the load average every 30 s, runs `check` before
  the first set, before the first final set and after the last, prunes cache copies and
  `io.log` after each set (sha256 + size in `deleted-files.jsonl`), and writes
  `b5_campaign.json` with R1-R6. A non-empty set directory is refused (never resumed).
* `diag` never runs under the lock, and refuses the final split until the final timing
  sets are done.

## Report (`scopt report --b5-campaign`)

One command renders every row; anything without data is `not_run` with a reason, never
0. Timing campaigns under the roots that are not sets of the B5 campaign are marked
`(foreign)` and never count as a B5 measurement.

| row | source | label |
|---|---|---|
| arms per split (measured / not_run / not_planned / skipped_unsupported / excluded) | campaign + campaigns found | — |
| paired BENCH speedup vs warm and vs parent, R11 flag | timing rows | MEASURED |
| removed lookups per run, predicted saving, DERIVED ns/lookup | v6 ext slots × profile `lookup_hit` edges (train; held-out/final base profiles from `diag`) | MODEL / MEASURED / DERIVED |
| removed env stores per run, DERIVED ns/store | NOP-filled `mov [rbp+d]` per unit vs the artifact's input cache × unit entries | MODEL / MEASURED / DERIVED |
| code growth | populated bytes, resized units, stub (Σ guard_len) and variant bytes, file/allocated/arena, Δ / hot set (99 %) | MODEL |
| memory | children max RSS; `.sc` sizes | MEASURED |
| full-harness throughput | wall per run, paired wall speedup | MEASURED |
| region coverage | SPEC-pair entry share and guarded lookup share (MODEL); links armed and C' hits (diag) | MODEL / MEASURED |
| cold path | `qemu.wait − BENCH` from `work/fastdyn_timing.jsonl`; `ext_load_ns` (diag) | DERIVED / MEASURED |
| fallback frequency | appended records per run; disarm and refusal counters (diag) | MEASURED |
| preparation cost | pass `duration_s` (sidecar); build/validate/V10 wall (prep) | MEASURED (tool time) |

The model reproduces the passes' own numbers on the gate-binary artifacts (unit tests):
guarded lookups equal the sum of `train_lookups_guarded` of the `b3` artifact, and the
removed store count equals `x_classes` of every WP29 B4 artifact.
