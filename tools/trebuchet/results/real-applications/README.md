# Real-application results

The release-image editor and flight missions have executed on ARM guest firmware. Each result below identifies its guest, cache state and application oracle. The archived synthetic benchmarks have no weight in these comparisons.

| Comparison | Verified outcome |
|---|---|
| Pye, training-only frozen cache on a held-out edit | On 12 scored pairs proofreading the editor manual, original-image SFB → B3 reduced median edit latency from 56.395 to 35.803 ms against original-image ordinary. The median of paired gains was **1.5275×** (95% bootstrap interval 1.437–1.579×). Both arms returned the entire expected document. Each started with 3,509 cache records. Both translated new paths during execution. [Final paired measurements](pye-training-frozen/final.json) · [Trial verification](pye-training-frozen/verified-trials.json) · [Selection and historical-control scope](pye-training-frozen/) |
| Pye, historical host-cache control | Six historical recipes qualified on the same repaired FirmBOLT guest. SFB → B3 beat its ordinary cache in 12 of 12 confirmation blocks, 1.278×. The seventh recipe, B4, failed symbolic validation. [Historical control](pye-historical-eligible/) |
| Pye, fully warm requirement | In the eight-sweep known-path experiment, the three transformed ranking warmups failed strict replay. The ordinary fallback then appended four translations in its confirmation warmup. This track has no final comparison. [Stabilization and raw observations](pye-stabilized-inventory/) |
| Pye, B4 and guarded UDIV | Reimported B4 replaced 3,421 dead stores in 2,555 TBs with same-width NOPs. Seven guarded UDIV splices added 224 bytes and kept the original divide-by-zero call paths. All three training runs passed the full document oracle. Ordinary, B4 and native appended four, two and two translations respectively. [Training and validator receipts](pye-b4-native-training/) |
| Pye, training diagnostics | On 12 balanced blocks, B4 gave 0.962× and guarded division 1.026× against original ordinary. Both 95% intervals span one. Sixteen configurations in the broader search passed the application oracle and appended translations. [Paired controls](pye-stage-controls/) · [Bounded discovery](pye-discovery/) |
| FirmBOLT load-segment correction on Pye and PX4 | The additional Pye load shrank from 198,184 to 68 bytes. The PX4 load shrank from 1,922,016 to 156 bytes and fit flash. Both executed relocated code and passed their application checks. A separate PX4 mission recorded 24,538,539 entries at 51 relocated TB starts. These two guest qualifications carry no speed measurement. [Image placement](../../applications/firmbolt-inspection/README.md) · [PX4 cold mission](../../applications/flight/evidence/px4-transformed-cold.json) · [PX4 executed region](../../applications/flight/evidence/px4-transformed-execution.json) |
| Pye guest relocation on stock QEMU, cacheless training edit | All 24 measured pairs passed the document oracle. Median paired operational speedup was 1.012× (95% interval 0.989–1.023×). [Absolute times, CPU costs and raw pairs](pye-stock-training/) |
| Pye ordinary and transformed cache preparation | The original-image two-sweep diagnostic materialized ordinary, B3, SFB and SFB→B3. The held-out ranking warmup added six TBs and stopped the comparison. A separate joint-image preparation preserved a successful zero-append FirmBOLT training replay and a failed original zero-append check. [Original registry](pye-original-known-inventory/) · [Joint preparation](pye-joint-preparation/) |
| ArduCopter and PX4 on their existing FastDyn ports | Each passed a cold mission, a cache population mission and eight cache replays. The eighth replay added 692 and 1,395 blocks respectively. Both applications reproduced the mission using a sealed, hashed initial inventory. [Raw-checked mission and cache receipts](../../applications/flight/evidence/hosted-qualification.json) |
| grblHAL and ESCape32 | grblHAL completed the drawing on the upstream simulator. The ARM controller session still needs board I/O validation. Both ESCape32 release inputs stopped at the STM32G071 PLL-ready poll. [grblHAL](../../applications/grblhal/) · [ESCape32](../../applications/escape32/) |
